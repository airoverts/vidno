# AGENTS.md — Vidno

## Проект

Vidno — веб-сервис для мониторинга и развития видимости бренда в AI-ответах. Основной пользователь — in-house маркетолог.

- `index.html` — лендинг и маркетинговые разделы.
- `dashboard.html` — отдельный рабочий интерфейс с левой панелью, live-проверкой и Планом роста.
- Личный кабинет клиента развивать внутри `dashboard.html`, не создавать для него отдельное приложение без прямого запроса.
- `css/style.css` — общий стилевой файл и дизайн-токены.
- `js/script.js` — логика лендинга.
- `js/auth.js` — клиентская проверка cookie-сессии и выход из аккаунта.
- `js/dashboard.js` — навигация dashboard, работа с API, live-проверка и План роста; `localStorage` используется только для локальных настроек интерфейса, например выбранного активного бренда.
- `backend/main.py` — FastAPI API.
- `backend/database.py`, `backend/auth.py`, `backend/storage.py` — PostgreSQL, авторизация и хранение рабочих данных.
- `backend/cache.py` — PostgreSQL-кэш запросов и результатов.
- `backend/gigachat_client.py`, `backend/deepseek_client.py`, `backend/yandex_client.py`, `backend/openai_client.py`, `backend/gemini_client.py`, `backend/perplexity_client.py` — провайдеры моделей и анализа.
- `backend/search_collector.py`, `backend/rag_analysis.py` — сбор источников и структурный анализ.
- `docker-compose.yml` — PostgreSQL, FastAPI backend, Nginx frontend и сервис резервного копирования PostgreSQL.

## Backend и данные

- PostgreSQL используется для пользователей, сессий, брендов, проверок и задач Плана роста. Основные рабочие данные dashboard не считать данными только из `localStorage`.
- Авторизация работает через HttpOnly cookie-сессии. Не возвращать и не хранить токен сессии в `localStorage`.
- `GET /api/health` возвращает состояние backend и провайдеров.
- `POST /api/check` и `POST /api/check-all` выполняют проверки AI-видимости; проверки сохраняются в PostgreSQL.
- Бренды, история проверок, задачи Плана роста и скрытые возможности доступны через пользовательские API и изолированы по пользователю.
- `DELETE /api/cache` очищает общий кэш и для удалённого вызова защищён административным токеном.
- Для локальной разработки frontend использует `http://localhost:8000/api`; при едином origin — `/api`.
- Профиль пользователя, управление доступом, админ-панель и восстановление пароля запланированы, но не являются готовыми функциями. Не описывать и не показывать их как реализованные до появления подтверждённого кода и проверки.

## Сервер

- Ubuntu-сервер доступен командой:

  ```bash
  ssh -o BatchMode=yes -o StrictHostKeyChecking=yes boss@192.168.0.101
  ```

- Каталог проекта на сервере: `/home/boss/projects/vidno/vidno`.
- Проект запущен через Docker Compose.
- Frontend обслуживается Nginx на порту 80; запросы `/api/` проксируются в FastAPI backend внутри Docker.
- Перед любыми изменениями на сервере сначала сообщить пользователю текущий известный статус и конкретный план действий.
- Перед любыми серверными изменениями обязательно выполнить:

  ```bash
  cd /home/boss/projects/vidno/vidno
  docker compose ps
  curl -i http://127.0.0.1/api/health
  ```

- Обновление проекта из GitHub выполняется из каталога проекта командой `./scripts/update-vidno.sh`.
- `./scripts/update-vidno.sh` запускать только при явном запросе пользователя на обновление или деплой.
- После обновления обязательно снова выполнить `docker compose ps` и `curl -i http://127.0.0.1/api/health`, затем сообщить пользователю результат обеих проверок.

- Не читать и не выводить токены, пароли, содержимое SSH-ключей и другие секреты.
- Не запускать команды, печатающие переменные окружения или содержимое окружения процесса/контейнера.
- Не добавлять секреты в код, логи, ответы, коммиты или команды.

## Дизайн

Единственный источник цветов — токены в `css/style.css`. Не вводить новые HEX. Использовать светлую палитру Vidno в контенте и `--night` только для разрешённых тёмных поверхностей, включая левую панель рабочего dashboard. При изменении цвета проверить и CSS, и захардкоженные данные Chart.js/градиенты в JavaScript.
